 # Exchange Matcher

   Vous gérez des mobilités internationales.

   Chaque année, des étudiants formulent des vœux qui peuvent décider d’un semestre, d’un parcours, parfois d’une
 trajectoire entière.

   Et pourtant, au moment de candidater, ils le font sans accès complet aux informations qui devraient être
 élémentaires :
   - leurs résultats complets
   - le niveau réel de concurrence
   - la pression sur chaque destination
   - le fonctionnement exact de l’affectation
   - les chances réelles d’obtenir un choix donné

   Autrement dit : ils doivent prendre des décisions importantes dans un système où l’information décisive ne leur est
 pas donnée.

   ## Le problème

   Ce n’est pas un problème technique insoluble.

   Les outils existent.
   Les méthodes existent.
   Les algorithmes existent.
   La logique d’affectation existe.

   Ce qui manque n’est pas la possibilité.
   C’est la volonté de rendre le processus lisible.

   ## Ce prototype montre

   Ce prototype démontre qu’un système d’affectation plus transparent, plus explicable et plus rationnel peut être
 construit simplement, avec :
   - des préférences étudiantes ordonnées
   - des capacités d’accueil visibles
   - des compatibilités de filière explicites
   - des critères académiques intégrés
   - un matching stable fondé sur Gale-Shapley

   En clair :
   un système où l’affectation n’est plus une décision opaque qui tombe d’en haut, mais un résultat compréhensible.

   ## Ce que cette démo remet en cause

   L’idée selon laquelle l’opacité actuelle serait normale.
   L’idée selon laquelle les étudiants devraient classer leurs choix à l’aveugle.
   L’idée selon laquelle il serait acceptable de demander des décisions sérieuses sans fournir l’information minimale
 nécessaire pour les prendre correctement.

   ## Ce que ce dépôt contient

   - un prototype web autonome
   - un profil étudiant simulé
   - un classement de vœux
   - une simulation d’affectation
   - une visualisation des résultats
   - une explication simplifiée de l’algorithme utilisé

   ## Utilisation

   Aucune installation n’est nécessaire.

   - ouvrir la démo en ligne
   - ou ouvrir `index.html` directement dans un navigateur

   ## Fichier principal

   - `index.html` — prototype front-end autonome

   ## Algorithme

   Le prototype repose sur une logique de matching stable inspirée de l’algorithme de Gale-Shapley, utilisé pour les
 problèmes d’affectation avec préférences ordonnées et capacités limitées.

   ## Conclusion

   Ce dépôt n’est pas seulement une démo.

   C’est une preuve.

   La transparence était techniquement possible.
   Elle ne l’était simplement pas dans le système actuel.
